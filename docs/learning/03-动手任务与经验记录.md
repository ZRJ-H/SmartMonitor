## 二、准备自己的实验位置

先在项目根目录确认工作树干净，再创建如 codex/learning-ownership 的学习分支。
创建前检查该名字是否已经存在；不替换已有分支。
普通测试使用临时目录/SQLite；涉及 MySQL 时明确使用 smart_monitor_verify_ 前缀库。
运行 MySQL 集成测试前需要准备已迁移的隔离库、环境变量和 QMYSQL 依赖，不能只改一个库名就假设完整。

每个实验结束后提供 `git diff`、测试结果、提交号。
不使用 git reset --hard 或 git clean 清理“不知道是什么”的文件。

## 三、第一项练习：补一个你能解释的边界测试

目标：让你第一次从需求推到断言。

文件：[tests/tst_event_recording.cpp](C:/QtProjects/day20_smart_monitor/tests/tst_event_recording.cpp:1)。
自己加入一个独立测试：
- 开始 event-a，消费一个采样点；
- reset 后开始 event-b；
- 新事件仍能在 0/1000/2000 ms 取得三张；
- event-a 的已采样次数不能污染 event-b。

先写你预测的状态变化，再写测试。不要仅把源码的 return 条件换个说法抄进断言。
如果现有实现已经通过，这表示补充了覆盖，不虚构为“修复了一个 bug”。

验收：你能解释 reset 要清理什么，也能说出漏清理会造成什么可见结果。

## 四、第二项练习：隔离复现，再判断是不是缺陷

候选问题：采集失败的具体原因是否很快被“预览已停止”覆盖？

查 [view/mainwidget.cpp](C:/QtProjects/day20_smart_monitor/view/mainwidget.cpp:1476) 和
[view/mainwidget.cpp](C:/QtProjects/day20_smart_monitor/view/mainwidget.cpp:1488)。
静态看存在先后覆盖的可能；这是待你复现的假设，不是本次已确认的新缺陷。

步骤：
1. 画出 errorOccurred 和 captureStateChanged(false) 的顺序。
2. 用测试对象或隔离输入触发失败，观察最终显示文字。
3. 如果重现，先写期望明确错误原因的失败测试。
4. 提出状态表达方式：正常停止与异常停止要否区分，错误何时清除。
5. 最小修改，检查正常停止、重新启动、另一通道都不受影响。

验收：讨论的是用户最后看见什么，不是只证明某个槽函数被调用。

## 五、第三项练习：文件与数据库两边都验证

不去关闭实际 MySQL 服务。用测试数据库“缺表/失败触发器”注入失败，
参考 [tests/tst_media_recovery.cpp](C:/QtProjects/day20_smart_monitor/tests/tst_media_recovery.cpp:1)。

你需要记录四列：
- 操作前：文件、行数、待办数量；
- 失败后：哪些保留，哪些没有提交；
- 修复依赖后：重放改变了什么；
- 再重放一次：为什么不重复创建记录。

再阅读孤立 JPG 的测试：为什么内容相同可以接纳，而另一个不明同名文件不该被覆盖。
验收：能区分“可重试”“幂等”“事务”三个概念，不能混用。

## 六、第四项练习：选一个小需求自己实现

二选一，先写设计和测试，再动业务：
- 日志筛选结果翻到空白页后，明确回到有效页或禁用下一页，保留当前过滤条件。
- 查看器上一张/下一张到边界时禁用相应按钮，明确只浏览当前页。

开始前先确认当前实际行为，避免重复实现已存在的能力。
实现要覆盖 0/1/整页/多页、筛选变化、删除后再查询等相关边界。
禁止为一个按钮变化顺便重写整个 MainWidget。

验收：你能解释代码放到哪层、为什么没有放进数据库连接类；演示改前与改后的区别。
到这一步，你就有自己的“需求—实现—测试—交付”小闭环。

## 七、第五项练习：准备优化，不立即动架构

先在固定输入下测量一段链，例如 frameReady 到 display_frame 的延迟。
写出采集时间戳、收到时间戳、样本数量、P50/P95、最大值怎么记录。
先不要为了加测量把耗时格式化日志打在每一帧上，以免测量本身成为瓶颈。

你要交的不是“准备用线程池优化”，而是：
“在哪个负载下，哪个指标变差；我要用哪组对照实验区分推理、编码、GUI 或 SQL 的影响。”

## 九、项目陈述练习

先用 60 秒概括用途和模块，再用 3 分钟讲一个你实际做过的改变。
结构是“场景 → 问题 → 证据 → 选择 → 实现 → 验证 → 边界”。

已有索引、时间轴和恢复修复可作为学习案例，尚未参与的部分不要写成自己亲手完成。

“我在既有 Qt 监控工程上负责某模块的验证和改进，通过某测试发现问题，选择某方案，得到某结果。”
