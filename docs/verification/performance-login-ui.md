# 性能、登录隔离与界面回归（2026-09-24）

## 已复现的问题

- 窗口管理器曾在未登录时直接展示监控；当前保留后台工作线程，只禁止未认证用户查看和操作。
- 隐藏的单画面通道仍生成 QPixmap，跨线程信号队列可无限持有大尺寸图像。
- 显示链路进行全尺寸 BGR→RGB 转换、两次复制，再缩小 QPixmap。
- 本机 OpenCV 默认 16 运算线程，四路 FFmpeg 默认解码带来大量线程及缓存。
- 实际设置页在默认/最小窗口高度下会压缩输入框，文字被裁切；改为有滚动区域的表单。
- 普通标签继承系统黑字，深色面板上的对比度约 1.54∶1；禁用与选择状态也不完整。

## 本机合成基准

同一机器、同一编译链，使用生成的媒体；原始 CSV、源码和方法保存在
`artifacts/verification/performance-audit/`。以下是部件测量，不代表整机或主程序改善百分比。

| 项目 | 原实现 | 新策略 |
| --- | --- | --- |
| 四路合成 1080p H.264 解码线程数 | 128 个 OS 线程 | 16 个 OS 线程 |
| 同一解码探针工作集 | 563.3 MiB | 149.4 MiB |
| 1080p→480×270 单帧渲染均值 | 6.69 ms | 0.45 ms |
| 4K→480×270 单帧渲染均值 | 25.77 ms | 0.42 ms |
| YOLO 单次推理墙钟时间 | 78.47 ms（16 线程） | 72.10 ms（4 线程） |
| YOLO 单次累计 CPU 时间 | 731.25 ms | 245.31 ms |

新策略为 FFmpeg 每路 2 线程、OpenCV 最多 4 线程、不可变 Mat 引用和先缩图后转换。
最终 QImage 还持有 Mat 生命周期引用；截图时才复制全尺寸像素。
摄像头打开方式保持 CAP_ANY，需结合实际设备测量。

## 自动回归与检查

根据用户澄清，登录权限与后台采集已分离；以本节当前语义为准。

先运行新增测试确认旧行为失败，再完成修复。主要覆盖：

- 未登录时后台工作线程运行，但 GUI 不接收和显示图像，窗口只显示登录页。
- 退出登录清空画面且保留后台线程；仅退出整个程序释放线程。
- 四路生成的 AVI 在首次登录前及注销期间持续推进，跨登录不重开源、不封口录像；析构后每通道仅一个录像可解码。
- 单画面隐藏通道不渲染，原分辨率截图保留正确颜色和像素生命周期。
- 1,000 帧突发邮箱只保留最新帧；两个线程交付 20,000 帧后正确结束。
- 真实 MP4 在首次打开、循环、停止和重新启动后都使用 2 个解码线程。
- 960×600 与 1280×760 的设置页输入框文字高度和滚动到保存按钮。
- 实际 Qt 控件的正常/非活动文本对比度至少 4.5∶1，禁用至少 3∶1；登录文字位于不透明卡片。

全部数据操作使用 SQLite 内存库，媒体在临时目录生成；硬件、生产媒体未参与自动测试。
详细结果见 `artifacts/verification/latest.json` 与对应测试日志。

## 仍需现场验收

真实四路摄像头、YOLO 完整约 60 秒事件、设备拔插、低磁盘、7×24 小时长稳未完成。
事件封口后的图片编码和入库仍在主线程，集中保存大批事件图片时可能短暂卡顿；
本轮没有把此路径或摄像头后端阻塞退出风险算作已解决。
