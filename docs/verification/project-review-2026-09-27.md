# 2026-09-27 项目审查与日志页整改

## 结论和范围

当前代码已覆盖进度表的主要功能，职责划分和可测试性明显改善；不能据此宣称整个项目已经完成交付验收。
本轮基于源码、隔离测试、实际播放器解码和界面截图检查。未连接生产数据库、未操作用户媒体、未修改进度表、未替换正在使用的旧程序。

需求依据：`周睿杰-智能监控系统_合并需求与10天开发计划.xlsx`，工作表“需求分析”B4:K15 和“10天进度计划”B4:L13，内容截至 2026-09-24。文件位于学习目录 outputs/smart_monitor_10day。

## 本轮发现和处理

1. **已修复：筛选作用域不清。** 原功能名称是 operation_func 完整匹配，只用于操作日志，却也显示在异常事件页。改为由 Model 查询真实操作名称，Service 提供列表，View 显示“全部操作”及已有名称；事件页仅显示时间与通道，操作页仅显示时间、管理员和操作名称。
2. **已修复：事件选择与导航互相冲突。** 原事件单击就播放，两个关联按钮始终显示且未选中时无反馈。现在单击只选择，按钮为“查看事件图片”“播放事件录像”，仅事件页显示；未选中禁用，无录像禁用播放，双击可播放。取消选择、刷新、查询失败和禁用页面后不能操作旧事件。状态改为“已完成”“已中断”，录像列改为“可回放”“无关联录像”。数据库 ID 保持不变。
3. **已修复：导航高亮错误与标签低对比度。** 图片、日志按钮加入导航互斥组，事件跳转也同步选中状态；补齐选中导航和页签的深色主题。
4. **已验证：媒体关联确实生效。** 使用内存库、临时 JPG/AVI，验证日志事件按钮只显示该事件的图片，排除无关图片；另一路跳转真实 QMediaPlayer，确认源路径、播放状态和 QVideoSink 解码帧。不是仅检查信号发出。

## 仍需处理或验证的事项

| 优先级 | 发现 | 依据及影响 | 建议 |
| --- | --- | --- | --- |
| 中 | 大量图片查询仍同步加载全部缩略图 | ImagePage::reload 查询所有匹配行，并在 GUI 线程逐张 reader.read；实际耗时取决于数量与磁盘，本轮未做大量图片压测 | 保留无分页连续网格，后续分批查询/按可见区域异步加载，避免恢复固定九张分页 |
| 中 | 本地文件事件与摄像头事件入口分离 | OperationLogModel::queryEvents 读取业务库 exception_log，SourceAnalysisWorker 使用独立 SQLite；日志页不汇总本地文件检测事件 | 当前补充页签提示，本地事件仍从回放页查看；若要求“日志包含所有来源”，需统一事件查询接口和来源标识 |
| 中 | 极端设备阻塞退出尚无验收证据 | MonitoringController::shutdown_workers 仍含 BlockingQueuedConnection 和无超时 wait；驱动若一直阻塞读帧，关闭窗口可能等待 | 用真实摄像头占用/拔插/驱动阻塞场景验证，再决定是否增加可取消采集边界；不能强杀写文件线程 |
| 必验 | 交付验收未闭环 | 真实四路摄像头、低磁盘、U盘导出、干净Windows与7×24小时均无本轮完成证据 | 保持开放，逐项留证；短时自动测试不能替代 |

以上待办未在本轮擅自扩展实现。图片数量导致的具体延迟和设备无限等待属于有代码依据的风险，未声称已在本机复现。

## 为什么比拆分前更好

- MainWidget 不再持有播放器、工作任务或页面内部控件，仅保留会话、导航和模块连接。
- PlaybackPage、MonitorPage、SettingsPage 分别持有页面状态；后台由 MonitoringController 和 MaintenanceController 管理。
- 页面不依赖 MainWidget 指针，控制器不依赖 QWidget。独立页面权限、迟到回调、线程所有权和重复退出可单独验证。
- 仍保留真实采集、录像和解码，拆分的收益是改动范围和定位路径更清晰，不代表性能、功能或安全性自动全部达标。
