# 本地视频事件移除影响评估（2026-09-29）

## 结论

用户本次要求评估移除影响，故此次保留本地视频事件链路与所有原始媒体，仅实施回放按钮合并。建议最终取消独立的“本地视频事件”页面，让需求中的普通录像/事件录像使用统一查询和回放流程；这需要先明确本地文件是否作为摄像头模拟输入承担录像与异常取证要求，不能只删一个标签即认为需求已对齐。

现有 AI 开发说明 REQ-05 要求四路分段录像，REQ-06 要求普通回看/智能侦测回看，REQ-07 要求异常关联录像和图片。当前实现却把本地文件作为独立索引源：不重复录像，每个事件一张代表截图，回放原始视频。与“三张自动截图、约60秒事件录像”的摄像头流程不同。历史说明也存在单/四画面检测策略变化；需求说明用于分析差异，当前用户指示优先，不能据旧文档自行改回所有旧行为。

## 三种移除范围

| 范围 | 对现有功能的影响 | 风险 |
| --- | --- | --- |
| 只移除回放页标签及查询入口 | 摄像头/历史录像列表、播放器控制、倍速、截图仍可用；本地原视频预览与检测可继续。独立索引事件失去查询、定位、看截图、重定位原文件的入口；后台仍分析和存储 | 中：界面简化，但留下不可见的后台功能与数据 |
| 同时移除 SourceAnalysisWorker | 本地视频采集/循环预览仍可保留；当前本地文件人形分析、绿框、事件样本、检查点、去重和代表截图消失；摄像头链路可独立保留 | 高：若仍需本地视频演示检测，会直接退化 |
| 取消独立入口，将本地文件纳入统一录像/事件流程 | 回放呈现更贴近普通/事件录像需求，但需实现本地文件录像/检测接入或经过确认的统一索引适配 | 较大改动：采集、检测、录制、存储、查询与历史数据兼容均需验证 |

## 代码证据与依赖

- view/playbackpage.cpp：本地视频事件标签、source_event_list_、分页/通道/历史筛选、play_source_event、截图查看、原视频重定位。
- view/mainwidget.cpp：回放页的 sourceEventsRequested/sourcePlaybackRequested/sourceRelocationRequested 与控制器绑定。
- service/monitoringcontroller.cpp：configure_file_analysis 分派本地文件；start_channel 的 record_channel_enabled_ 仅对 Camera 为真；on_source_ready 与 on_person_detected 排除 File。因而删除列表后，本地文件不会自动进入历史录像表。
- service/monitortask.cpp：实时 DetectionWorker 仅处理 Camera；File 的检测框来自 SourceAnalysisWorker::boxesReady，不能直接删除分析器又期望本地视频继续画框。
- service/sourceanalysisworker.cpp：独立 source-index.sqlite 中的 assets/analyses/samples/events/channel_analysis/analysis_channels；截图位于该索引目录 screenshots。与业务录像/图片表不是同一套检索链路，不会自动出现在摄像头历史录像或图片管理列表。
- 摄像头事件仍通过 RecordTask / StorageWorker 保存，可在隔离测试下保留原功能，不必因取消文件索引而改业务表。

## 建议实施顺序

1. 若本地文件用于模拟监控源，先把 File 接入普通分段录像、实时检测、事件录像和图片关联流程；保留原视频，避免循环播放无限重复事件需要另行确定去重/循环策略。
2. 统一回放页为普通录像和事件录像查询（时间、通道、类型筛选），复用现有 QMediaPlayer。完成替代后删除独立标签和信号连接。
3. 停止不再需要的文件索引任务与热切换分支，更新线程数量与流程测试。若保留索引仅作内部加速，需保留管理/清理说明，不能声称后台已移除。
4. 旧 SQLite 索引和 screenshots 先保留归档，不删原视频、不清业务库；若后续需要数据迁移，明确表结构、备份并在隔离库验证后再实施。

## 验收重点

摄像头及本地文件四路预览不受影响；普通/事件录像均可检索与回放；异常图片及关联跳转符合最终需求；循环文件不会无上限制造重复事件；换源/停用/退出不会接收旧分析结果；CPU/GPU切换仍作用于保留的检测链路；旧数据可恢复。若取消本地分析，界面与说明必须明确其不再支持检测。

## 本次实施的按钮合并

四按钮改为两个：停止/结束/失败后显示“播放”；播放中、暂停中或等待原视频校验时显示“停止”，可取消待处理请求。第二个按钮随真实 QMediaPlayer 状态显示“暂停”或“继续”，停止/校验中禁用。保留原公开 play_selected_record / pause_playback / resume_playback / stop_playback 槽，兼容现有调用。
